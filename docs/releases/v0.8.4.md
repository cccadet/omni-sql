# omni-sql v0.8.4

- Extends CI coverage and release wait timeouts to allow a clean build of the embedded DuckDB while retaining CI and SonarCloud approval requirements.
- Fixes Windows startup when migrating analytical data from a database file that is already open.
- Recovers backend authentication after a slow startup and continues checking readiness after the initial timeout.
- Improves MongoDB SQL diagnostics for missing fields, quoted text values, collection lookup and incompatible types. Conversion errors show the supplied and expected types when available and suggest `list_contains(field, value)` for array membership.
- Preserves inferred array element types, including nested lists, in result metadata and column tooltips.
- Includes native MongoDB autocomplete for databases, collections, operations, sampled fields, operators and aggregation stages, plus the corrected initial query template.
- Includes `/mongo` to convert supported SQL SELECT queries into native MongoDB JSON, including projections, filters, grouping, aggregates, HAVING, ordering and limits.
- Includes Windows NSIS, Linux DEB and macOS Apple Silicon/Intel DMG installers. macOS builds use ad-hoc signing; authorize the first launch in System Settings → Privacy & Security → Open Anyway.

MongoDB SQL types are inferred from sampled documents. For a text array, use `WHERE list_contains(id_guia, '52712827')` instead of comparing the array directly with a text value.

See [MongoDB usage and conversion limitations](../MONGODB.md).
