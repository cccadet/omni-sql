# omni-sql v0.25.0

- DuckDB memory limit: while an S3/DuckLake, DuckDB or MongoDB connection is active, the status bar shows the DuckDB memory limit (512 MB by default). Click it to choose a limit from 256 MB to 32 GB. The choice is kept between sessions. Queries that need more than the limit use a temporary folder on disk (up to 4 GB).
- The connection picker of **Add a table from another database to the JOIN** now shows each connection's environment tag.
- The Windows installer now asks for its language (English, Português (Brasil) or 简体中文) and runs in it. On first launch, omni-sql opens in that language. Without one (macOS, Linux, portable copies, silent installs), it follows the system language and falls back to English. A language picked in the app's settings always wins, so updates never change it.
- Fixed: large S3 and DuckLake queries, such as window functions or sorts over many rows, failed with "File system LocalFileSystem has been disabled by configuration". They now use temporary disk space; reading local files from S3 SQL is still blocked.
- Fixed: adding an Oracle table or query with `TIMESTAMP` columns to a JOIN failed with "source query failed". `DATE` and `TIMESTAMP` values now import with full precision, and `DATE` values no longer shift to UTC.
- When an Oracle source repeats a column name, the error now asks you to alias the columns.
