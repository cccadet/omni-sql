# omni-sql v0.23.0

- MCP: agents can now work on more than the active connection. A new `listConnections` tool returns the connections exposed to MCP with their dialect, MCP access level and environment (for example Staging or Production), and `getActiveConnectionContext` now includes the environment too. `executeSql`, `getSchemaSummary`, `getTableIndexes` and `explainSql` accept an optional `connectionId`.
- MCP approval dialog: SQL proposed for execution now has a **Run on connection** selector. It starts on the connection suggested by the agent (or the active one), you can switch to any connection that allows MCP access, and the query runs on the one you pick. The dialog shows the environment, warns about Production and when the connection is not the active one, and blocks running write SQL on read-only connections.
- MCP approval dialog: suggested SQL is now shown with the editor's syntax colors instead of plain text.
- Connections with MCP access set to **Off** are never listed to the agent or usable through MCP.
