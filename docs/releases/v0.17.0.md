# omni-sql v0.17.0

- Add an MCP access setting to each connection: Off, Read-only or Read and write. Off hides the connection from MCP tools entirely; Read-only allows schema reads and a single read statement (SELECT, WITH, VALUES, SHOW, DESCRIBE or EXPLAIN without ANALYZE; MongoDB find and aggregate); Read and write keeps the previous behavior, with desktop approval for every execution.
- Connections default to Read-only, including existing connections. To let an agent run approved writes again, choose Read and write in the connection settings.
- The desktop refuses disallowed SQL before showing the approval dialog, and the backend enforces the same rule again, so an approval never widens a connection's permission. On PostgreSQL, MySQL and MariaDB, read-only statements run inside a read-only transaction that is always rolled back, which also blocks writes hidden behind functions.
