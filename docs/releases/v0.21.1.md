# omni-sql v0.21.1

- Linux: on systems without unixODBC, omni-sql installed from the `.deb` opened its window, but the SQL editor stayed on "Loading..." and MCP showed as inactive. The backend failed to start because it couldn't load `libodbc.so.2`. The `.deb` now depends on `libodbc2`, so `apt` installs it automatically. ([#28](https://github.com/cccadet/omni-sql/issues/28))
- If the ODBC library is still missing, only ODBC connections fail now, with an error that names the package to install. Every other database keeps working. Before, the whole backend failed to start.

If you installed v0.21.0 on Linux and the editor never loaded, run `sudo apt install libodbc2`, or install v0.21.1.
